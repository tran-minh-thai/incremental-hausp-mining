# The machine every timing in the paper is measured on.
#
# Declared by the author on 2026-09-25: from that date every measurement runs on a Windows
# machine with an AMD Ryzen 9 9950X and 64 GB of RAM; the MacBook that measured the earlier
# campaigns is a development machine only. It is a declaration, not a detection: nothing here is
# inferred from whatever machine happens to be running, because a wrong guess would quietly
# license timings from a machine that was never meant to produce them.
#
# Only the runtime and memory numbers depend on this machine. Counts -- patterns, candidates,
# tightness, exactness verdicts -- are determined by (commit, data, seed, library versions) and
# reproduce anywhere; that is why results-invariant/ exists and why this file does not gate it.
#
# scripts/campaign.py refuses to run a non-probe plan on any machine but the "host" below, and
# analysis/check_measurement_machine.py refuses any timing artifact whose provenance line names
# a different machine.
#
# The host name is left empty on purpose until the validation plan (scripts/plans/validation.json)
# has run on the new machine: it is then copied from the provenance line that run writes, which
# is how the JVM itself names the machine, so the two can never disagree.

host        =
cpu         = AMD Ryzen 9 9950X
memory      = 64 GB
os          = Windows (version recorded by the campaign ledger)
jvm         = JDK 25 (the exact build is recorded by the campaign ledger and in every provenance line)
heap        = 24g   (-Xmx of every run, fixed in scripts/campaign.py; part of what an OOM means).
              Below 32g on purpose: from 32g the JVM stops compressing object references, which
              inflated the object-heavy baselines' live heap more than the proposed algorithm's
              (results-probe/oops-test).
time limit  = 90 minutes per batch (scripts/campaign.py, passed as --timeout)

# Conditions a campaign holds, and which a reader should assume:
#   - the machine does not sleep: scripts/campaign.py holds SetThreadExecutionState for the whole
#     campaign, so this does not depend on the command line;
#   - on mains power, Windows Update paused for the whole campaign, power plan at high
#     performance, the repository folder excluded from real-time virus scanning, no other heavy
#     process. The driver cannot set these; it prints them before starting;
#   - one campaign at a time on this machine, of this project or any other;
#   - the checkout is not pulled while a campaign is unfinished.
#
# Earlier artifacts: every result tree measured on the MacBook (ThaiTMs-MacBook-Pro.local) was
# deleted from the working tree on 2026-09-25 and remains in the git history before that date.
